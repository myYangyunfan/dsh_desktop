## 二、第三方供应商模型消失：根因与 boot 链自愈

### 根因链（alpha.4 实测）

dsh-llm-pi-ai 的 `apply()` 对 providers 数组做全量校验：任一供应商条目缺
`api`/`baseURL` 等必需字段 → 整个插件启动失败 → 该插件承载的全部第三方模型
（qwen-token-plan-cn、jiyuan 等）从模型列表消失。官方模型不受影响，极易误判为
「供应商跑路」。

### 修复（`scripts/lib/pi-ai-settings-heal.js`）

- boot 链新增自愈步：扫描 settings.yaml 的 llm-pi-ai providers 配置，非法条目
  自动降级为禁用注记（保留原文供恢复）并写回合法配置
- 效果：一家供应商配置非法不再拖垮整个插件；官方模型与其余第三方供应商全部恢复
- 测试：`unit-pi-ai-settings-heal.test.js` 13 项 + 全量 1744/1744 通过

## 三、safe-boot 补 import 形态识别

### 缺口

`parseFailedLoaderIds` 此前只认 `failed to apply loader entry`（应用期失败）。
内核 alpha.x 模块表严格化后出现 import 期失败形态：

```
failed to import loader entry 9c5ab60c (@linxin666/dsh-desktop-launcher):
client-modules: require("@deepseek-ai/dsh-client-runtime/client") missed the
module table — ...
```

旧版 @linxin666/dsh-desktop-launcher（0.2.9~0.3.6）依赖已移除的
`@dsh-client-runtime`，用户从 5.4 升 5.5 起每次启动都弹同一错误——safe-boot
从未识别该形态，自动禁用闭环失效（5.5→5.6 连续复现）。

### 修复

- 正则补齐 `(?:apply|import)` 两期形态；错误详情里的 require 目标
  （`@deepseek-ai/dsh-client-runtime/client`）不得误抓
- 端到端验证：用户真实错误文案 → `safe-overlay` 生成含
  `@linxin666/dsh-desktop-launcher` 的禁用 overlay（@ 包名 YAML 引号化）
- 用户侧解法：插件管理里更新 launcher 至 0.3.12+（已适配 alpha.4，
  `engines.dsh: ">=0.1.2-alpha.4"`）

## 七、dsh-cardian 工具名净化补丁落地（双前缀 bug）

- 根因：`patch-target-resolver.js` 中 `DS_LLM_DEEPSEEK_PKG_REL` 曾误含 `@deepseek-ai`
  段，而 `mkAi()` 已自带 scope 前缀，导致 `ds-tool-schema-sanitize` 补丁目标路径出现

## 八、跨内核「覆盖安装」boot 失败根治（vendor 陈旧内核 tarball 自愈）

### 现象与根因

跨内核版本覆盖安装（如 0.5.x → 0.6.0）后 app 起不来、转恢复页；`desktop.log` 铁证
`boot 步骤 compat-pin FAIL: kernel-pin 与 vendored 内核不一致` → `sidecar-boot FAIL`。
根因：NSIS 覆盖安装只做「增/覆盖」不做「删」——旧安装 `vendor/dsh-kernel` 里上一版
内核的 242 个 tarball 不被清除，与新版叠加成版本混装；`validate-pin.js` 的版本混装
防线按 `f.includes(packageVersion)` 判定，任何非 pin 版本 tgz 即 fail-closed 拒启。
发布包本身干净（仅含单一版本），缺陷仅在覆盖安装态触发，故每次内核升版覆盖安装都会复发。

### 根治（boot 运行期 repair 步自愈）

- 新增 `scripts/lib/vendor-kernel-heal.js` 的 `healVendorStaleKernels({ appDir, log })`：
  复用 `validate-pin` 的 `loadPin`（单一真值源、判定谓词完全一致），把 vendor 里非 pin
  版本 tarball **移出到 sibling 隔离目录** `vendor/_dsh-stale-kernel-quarantine/`（非破坏、
  可回退、幂等）。接入 boot 链 **repair 步**（`integration/index.js` 的 `healBeforeServer`，
  位于 compat-pin 之前）——覆盖安装后首次 boot 即自愈，无需重装。
- **宁漏勿误守护**：pin 不可读 / 无 packageVersion / vendor 缺失 / 无 tgz 一律不动；
  匹配 pin 版本的 tarball 数为 0 时**绝不剪**（防掏空 vendor），只日志交 compat-pin 精确报错；
  全容忍 try/catch，任何子失败绝不阻断启动。
- **验证**：新增 `unit-vendor-kernel-heal.test.js` 5 项（混装→剪除→validate 由 FAIL 转
  PASS / 干净 no-op / 全陈旧拒剪 / vendor 缺失跳过 / 幂等），全绿。
- **打包面根治**：`stage-payload.sh` vendor 段补 `mirror_dir vendor/dsh-kernel` 全量镜像；
  CI `tauri-release.yml` 五个平台 job 的 Stage payload 步骤均补 `cp -r vendor/dsh-kernel`。
