# DSH Desktop v0.5.7 — 全平台

> 本版本是 **0.5.6 之后的修复 + 功能恢复版本**：删除/归档对话功能回归（含必炸根因
> 修复）、侧边栏交互全面 VSCode 化、spawn 环境净化根治外部注入崩溃环、内置 8 个
> 社区预设（署名齐全）。

## ⚠️ 重点 1：删除/归档对话功能回归（v0.5.6 中随内核升级退役）

`dsh-session-manager` 在 v0.5.6 因内核 RPC 重写退役，本版本恢复回归并完成两件事：

- **宿主 RPC 重靶**：`workspace.deleteSession` / `workspace.unarchiveSession` 重靶到
  `dsh-api-workspace-controller`（index / typert.host / client）+ `dsh-api-remotes` +
  `dsh-session` + `dsh-workspace` + `dsh-client-ui-workspace`（7 锚点全命中、增量幂等）。
  实测新内核 `0.1.2-alpha.1` 无原生 deleteSession，monkey-patch 仍必要。
- **「点击删除无任何反应」根因修复**：重靶宿主访问 `ctx.agents` / `ctx.sessions` /
  `ctx.sessionPersistence`，但 `WorkspaceController` 的 cordis `static inject` 只声明了
  `[typert, workspaceRegistry]` → cordis 直接抛 `cannot get property "agents" without
  inject` → commandError → 桥 catch → `window.alert` → 而 polyfill 的 alert 转发只写
  stderr，release 壳（`windows_subsystem="windows"` GUI 子系统）无人接收——表现为
  无弹窗、无报错、零日志（诊断探针实证：修复前假 id 调用 RESOLVE:false + 报错蒸发，
  修复后 RESOLVE:true、菜单 E2E 真实点击全链成功）。

**配套根治**：

- 补丁幂等策略从「全局 MARKER 整文件跳过」改为**逐替换项增量判定**——存量已打补丁
  副本下次启动自动拿到修复，无需重装
- `page_error` 双写 `desktop.log`：GUI 子系统 stderr 蒸发导致的「报错不可见」诊断盲区
  根治（此前 alert 的真实拒因会直接消失）

## ⚠️ 重点 2：spawn 环境净化根治（外部注入崩溃环）

**真实事故**：外部环境（WorkBuddy）通过 `NODE_OPTIONS=--require=…genie-safe-delete.cjs`
把 `fs.rm` 猴补丁注入内核，boot 期批量删除被拦 → 内核启动即崩 → 崩溃环 → 恢复页，
且伴随 97 个共享模块指向损坏。

- **全部执行 DSH JS 的 node spawn 统一走 `sanitized_node_command`**（`env_clear()` +
  `ENV_ALLOWLIST` 白名单），覆盖内核主 spawn 与 sidecar / guard / watcher /
  koffi-preflight / balance 等 9 处；纯系统命令不受影响
- 白名单补齐 macOS/Linux 必需集 `TMPDIR / USER / LOGNAME / SHELL / TERM` 与
  `DSH_TAURI_USERDATA / DSH_TAURI_DIAG`；balance 侧显式回传
  `HTTPS_PROXY/HTTP_PROXY/NO_PROXY`（保住余额取数的代理语义）
- 顺带根治：sidecar 被 `env_clear` 剥掉 `DSH_TAURI_USERDATA` 后回落真实 APPDATA、
  误写 `safe-boot.overlay.yml` 禁用健康插件的事故链

## 🎨 侧边栏（dsh-better-sidebar）三连

- **文件树点击语义对齐 VSCode**：左键/回车/搜索结果 = 右侧分栏预览；右键菜单
  「预览」= 全预览区；「在新 Tab 中打开」保留
- **聊天流文件名点击进侧边栏**：tool 行路径链接 / produced-files / 正文文件提及统一
  走 `remote.session.openWorkspacePath`，接管进侧边栏预览（带回落兜底）。实证旧拦截
  器包装的 `ctx.workspaces.openPath` 在新内核从未生效
- **修复并排布局回归**：原地打开文件继承首页 `treeOpen:true`，树默认 240px 把预览区
  挤到 0；现从 explorer 首页打开文件自动收起树、返回首页恢复

## 🧩 插件与设置

- **无效插件条目体检 + 一键清理**：插件管理页横幅透出指向不存在包的条目（如手改
  错拼 `skill-filesysem`），清理前自动备份 + 原子写入 + 幂等；`disabled: true` 但 id
  失配的陈旧记录单独透出
- **设置写入半补丁修复**：settings-models 幂等判定 `||`→`&&`，「只打 namespace-heal、
  缺 conflict-retry」的半补丁文件重跑被误判已完成的真实缺口补全
- **识图 apiKey 占位提示**：secret 字段脱敏永不回显，重开空栏加「已保存（不显示
  密钥）；留空 = 保持已存密钥」占位，消除误判
- **冒烟脚本单实例前置守卫**：检测到已运行实例即拒绝执行（此前会误报 FAIL 且
  强杀用户正在使用的实例）
